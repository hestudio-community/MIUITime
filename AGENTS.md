# AGENTS.md

MIUITime: LSPosed/Xposed module (legacy API 82, pure Java, no UI) that restores the MIUI 12h status bar clock on HyperOS and hides the status bar clock on launcher pages containing an official clock widget.

## Build / verify / deploy
- Build: `./gradlew assembleDebug` (APK at `app/build/outputs/apk/debug/app-debug.apk`). Static check: `./gradlew lintDebug`. Unit tests (JVM: log parsing + hide-gate logic): `./gradlew testDebugUnitTest`.
- The Gradle daemon JVM is pinned in `gradle/gradle-daemon-jvm.properties` (`toolchainVersion=25`, auto-provisioned per-OS/arch via foojay toolchain URLs), so any machine can build without a local JDK setup. AGP 9.4.1 requires JDK 17+ and Gradle 9.x (wrapper is 9.7.1, needed to run on JDK 25). Never put machine-specific paths in tracked files (`org.gradle.java.home=/Applications/...` once broke every non-macOS checkout; `local.properties`/`keystore.properties` are gitignored for this reason).
- `app/build.gradle.kts` sets `enableKotlin = false` (the supported per-module opt-out of AGP 9 built-in Kotlin); without it AGP injects kotlin-stdlib into this pure-Java module (~2.4MB APK). Don't replace it with `android.builtInKotlin=false` in `gradle.properties` — that flag is deprecated and removed in AGP 10.
- Deploy: `./gradlew installDebug` (builds and installs in one step; the LSPosed-recommended install path for module developers). With multiple devices attached, set `ANDROID_SERIAL=<id>` first.
- A first install of a new package may fail with `INSTALL_FAILED_USER_RESTRICTED`; retry while the phone screen is unlocked (an on-device confirm dialog appears).
- `installDebug` signs with `~/.android/debug.keystore`; if a differently-signed build (e.g. `app/release/app-release.apk`) is installed on the phone, uninstall it first or install fails with `INSTALL_FAILED_UPDATE_INCOMPATIBLE`.
- Reload after install: `adb shell am crash com.android.systemui` (`am force-stop` is ignored for SystemUI). Verify with `adb logcat -s MIUITime:V`.
- This directory is a git repository (branch `main`). Don't commit secrets (`keystore.properties`) or machine-specific paths.
- Target device verified: Xiaomi HyperOS 4 (Android 17), SystemUI `17.03.260226`, launcher `8.01.02.7719`.

## Non-obvious architecture
- **Never try to hook `com.miui.home`.** The HyperOS 4 launcher is a native process (`hasCode=false`, spawned by `hyos_spawner`, entry `libapp_launcher.so`); LSPosed cannot inject into it (HyperCeiler can't either). Former `LauncherBridge`/`WidgetRecon` recon code was provably unreachable and has been deleted — don't recreate it.
- Feature 2 detection lives entirely in SystemUI and parses the launcher's own logcat (`LauncherLogMonitor`). SystemUI runs as uid 1000 with gid 1007 (log), so it may read logs. Signals:
  - `[Info][LayoutInfo] overview: ... currentScreenId=N` + `screen(index: N, id:S, ...)=>(items)` — settled page layout incl. widget title/type/pkg.
  - `AllAppsTransitionController setState...: state=...` — `normalState` vs `allAppsState`/`overViewState`/`assistantOverlayState`; only `normalState` may hide the clock.
- Clock widget matching: widget items (`type=maml|appwidget|gadget`) from `com.android.deskclock`/`com.android.alarmclock`, OR built-in MAML with an empty package (`pkg=#<uuid>`/`pkg=null`) whose title contains `时钟`/`clock`. Never match `type=application` (that's the clock app icon). Only desktop items (`container=-100`) count — folder (positive container) and hotseat (`-101`) items never hide the clock, in every log stream.
- Stacked widgets (堆叠组件): the `screen()` snapshot lists only the container (`type=stackedWidget(1003)`, `pkg=` empty) — its title tracks one member and **must never be matched as a clock**. Members appear only in the item streams with `extendContainer=<containerId>` (snapshot items carry the same field as `ext=`) and live in a separate stack registry (a complete snapshot replacement would otherwise drop them). A stacked page hides the clock only while its **top** member is a clock widget; top is followed via `[Warning]StackedWidgetManager [STACK-CONSISTENCY] getCurrentDisplayWidget: currentDisplayWidgetId=A != last=B, stackId=S`, `MamlVisibility | evaluate | ... tag=<id>_stacked ... stackBlocked=false` (also the cold-start initial top), and `MamlWidgetGetxController onVisible | mamlId=N tag=<id>_stacked`. Buried members and unknown tops never hide (fail toward show).
- The clock-page inventory is fed from three launcher log streams, not just the `screen()` snapshot: `ItemDataProcessor processItem` (cold-start item load — the initial `screen()` snapshot is emitted *before* items load with `itemsCount:0 0` and never re-logged), `[LauncherModelManager] insertItem/deleteItem/updateItemBatch` (shortcut-menu 删除 only logs `deleteItem`, no new snapshot), and `screen()` snapshots. Empty/truncated snapshots only upsert; they never clear known items (fail toward showing the clock). `LauncherLogMonitorTest` is fed with real captured log lines.
- Hide/show reuses `HomeStatusBarViewBinderInjector.hideClock/showClock(false)` → `MiuiClock.setPolicyVisibility(4|0)`, plus a `View.GONE` collapse of the clock so its layout width is freed (plain INVISIBLE leaves a blank gap in front of the status bar notification icons when 通知栏图标显示 is on); `ClockPageController` hooks `setPolicyVisibility`/`View.setVisibility` to enforce the hidden state.
- **SystemUI's `handleBindApplication` is on the keyguard critical path at boot — keep it minimal.** `handleLoadPackage` only installs the cheap early hooks (MiuiClock constructors / `updateTime` / `setPolicyVisibility` / `View.setVisibility`); `DeferredInit` runs everything else (ClockPageController, `LauncherLogMonitor` regex compilation + `logcat` child, task-stack/injector hooks) on a background thread after `sys.boot_completed=1` (60s fallback; instant after `am crash` self-heal). Slowing SystemUI bind delays the keyguard and briefly exposes the interactive launcher before the lock screen — see `docs/boot-keyguard-exposure.md` (measured: 4880→3034ms bind, 10.5s→3.9s exposure window).
- The `View.setVisibility` enforcement hook is process-wide and lands on SystemUI's hottest view path: its callback may only do one volatile read (`SystemUiClockHook.setForceHide`, published by ClockPageController) and an identity check against the captured clock — never reflection, binder or id-equality matching (id matching wrongly GONE'd other `clock`-id views, incl. keyguard clocks).
- Hide gate (`ClockPageController.computeForceHide`, unit-tested) defaults to showing: no hide before `sys.boot_completed`, before the first unlock after boot (one-shot `keyguardGateOpen`, never re-closes so unlock can't flash the clock), or while the launcher is not foreground.
- Foreground test: `ActivityManagerWrapper.sInstance` (OS4 removed `getInstance()`) + home-activity whitelist (`com.miui.home.launcher.Launcher`, `SecondaryDisplayLauncher`, `safemode.SafeLauncher`). All other `com.miui.home` activities (settings/recents/pickers) must show the clock. Fallback: `ActivityTaskManager.getService().getTasks(1)`. Runs on the `MIUITimeProbe` background thread with cached reflection (wrapper/ATM methods resolved once) — never inside a visibility hook.
- Feature 1 hooks `MiuiClock.updateTime()` and only rewrites instances whose resource entry id is `clock`; 24h mode is left untouched. Format is `aa h:mm` (→ `下午 3:48`).
- Scope is `com.android.systemui` only. Recommended scope is the manifest meta-data `xposedscope` → `@array/xposed_scope` (`res/values/arrays.xml`); an `assets/xposed_scope` file is ignored by LSPosed and was removed on purpose.
- Entry: `assets/xposed_init` → `net.hestudio.miuitime.XposedEntry`.

## Working on it
- Log tag is `MIUITime`; `XLog` mirrors to logcat and the LSPosed log.
- Launcher log parsing is undocumented and may change with launcher updates: keep regexes tolerant and fail inert (never mis-hide). `ClockPageController` adds a 250ms apply debounce, 3s polling while on a clock page (1s while the post-boot keyguard gate is still closed), a retry after SystemUI cold start, and out-of-band state probes (`MIUITimeProbe`) that feed the `forceHide` flag read by the visibility hooks.
- Device regression checklist for feature 2: reboot → first entry on a clock-widget page must hide, page swipe clock↔non-clock, shortcut-menu 删除 clock widget must restore (no page swipe), add clock widget must hide, clock widget in a folder/hotseat must NOT hide, drawer open/close, recents, assistant overlay, open app + return, launcher settings, SystemUI restart (state must self-heal). Stacked widgets: clock on top must hide / buried must show (flip via vertical swipe on the stack), initial top after reboot (no flip yet) must be respected, delete the top clock member must restore without page swipe.
- No UI by design (no launcher activity); install/manage via adb + LSPosed only. Don't re-add an activity unless asked.
